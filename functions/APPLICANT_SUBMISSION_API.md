# Applicant verification API (isolated emulator only)

Applicant routes are enabled only by the local emulator launcher after the exact demo project and loopback Auth and Firestore hosts pass the emulator safety checks. The launcher takes `OPT_DOCUMENT_STORE_ROOT` for an existing private local document directory. The ordinary local server does not enable these routes. All requests require the local server's existing Host and Origin checks and an active Firebase ID token in `Authorization: Bearer <token>`.

* `POST /api/applicant/draft` accepts JSON `{requestId, accountType, submittedFields}`. `requestId` is 32 lowercase hexadecimal characters generated by the client and must be retained for retry. The server creates the submission ID. Reuse with different fields is rejected. UID is always derived from the token.
* `POST /api/applicant/upload/{requestId}` accepts raw PDF, PNG or JPEG bytes with the corresponding Content-Type. The server assigns the document filename and computes its hash. The maximum is 50 MiB. Repeating identical bytes is safe; different bytes cannot replace the stored document. If the upload was interrupted, retry the same request ID and bytes.
* `POST /api/applicant/finalize` accepts JSON `{requestId}`. Repeating a successful finalization is safe. A missing, invalid or incomplete document cannot be finalized.

Incomplete requests live in `verification_upload_drafts/{uid}/requests/{requestId}` and never enter the pending queue. A completed upload creates a draft revision. The trusted finalizer changes that revision to submitted and synchronizes profile status in a transaction. Existing assignment, review and supersession rules remain in force. Practice Owner finalization requires its existing profile. Admin-only APIs remain separate.

The emulator Firestore rules deny direct client reads and writes; backend Admin SDK operations bypass those rules. This API is not enabled for production, not a mobile integration, and does not resolve deployed rules or directory availability. Document content validation checks file signatures, not full parsing or malware. Protect the private store, its key and backups as documented in LOCAL_DOCUMENT_STORE.md. No submitted fields, tokens or document contents should be logged.
