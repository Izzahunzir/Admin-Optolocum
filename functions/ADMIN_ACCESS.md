# Administrator access: operator procedure (isolated emulator only)

`admin_access.js` is not exposed through HTTP. `emulator/admin_access.js` is an operator-run process that first requires the exact demo project and loopback Auth and Firestore emulator configuration. It never grants an admin custom claim. For an existing, independently trusted and enabled Auth administrator, run `node emulator/admin_access.js bootstrap UID` in the configured emulator environment. Bootstrap validates the current Auth claim, creates or recovers `account_access/{uid}`, revokes refresh tokens, and activates access with a fresh `validAfter` cutoff. The administrator must sign in after that second. This operator channel does not require a working admin access record, avoiding circular recovery.

`disable UID` blocks the access record before disabling the Auth account and revoking sessions. `remove-admin UID` blocks the record, removes only the admin claim, and revokes sessions. None of these operations deletes an account. Failures after the block leave access disabled with an operation marker unless a final transaction committed but its response was lost. Inspect both Auth and the access record and retry the same operation; a conflicting marker fails closed and requires operator review. Do not use the procedure to create administrators or modify arbitrary accounts. Local process and credential access are the authorization boundary; restrict the host and operator identity.

Firebase Auth and Firestore cannot change atomically. An out-of-band disable or removal of an admin claim can leave an active record and previously issued token until expiry. Route all such operations through a trusted synchronized operator process, restrict IAM/console access, audit and reconcile drift. The isolated implementation is not a production bootstrap tool, does not monitor external Auth changes, and does not establish production IAM or deployed Firestore protections. The normal local server and deployed functions retain their existing gates; only the explicitly emulator-gated local API checks these access records for admin HTTP operations.
