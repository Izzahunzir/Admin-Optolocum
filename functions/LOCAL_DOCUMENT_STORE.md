# Local verification document store

The local backend accepts `OPT_DOCUMENT_STORE_ROOT` as an absolute existing private directory. It must be outside the MobileApp workspace and every web-served directory. No directory is created automatically. On Windows, provision a protected ACL that grants inheritable access only to the service account (full control), SYSTEM and local Administrators. The store rejects inherited ACLs and other allowed principals. On POSIX, the directory must be owned by the service user with no group or other permissions. Start the local service under that same account; it listens on 127.0.0.1.

The store exposes `put({uid, submissionId, name, contentType, stream})`, `verify(document)`, and read-only `reconcile(documents)`. The authenticated applicant upload endpoint uses this adapter in the emulator and the explicitly selected real verification mode; the authorized Admin document endpoint reads through it. The signature check identifies file headers, not complete structural validity or malware. The stored key must be backed up with the files; losing it makes identifiers unrecoverable. Never put a private root on a web server path or a shared drive.

The adapter atomically links a private temporary upload to a keyed identifier and refuses different bytes at that identifier. Verification reads and hashes the entire file before returning a stream of that verified snapshot. This prevents adapter-level replacement; it cannot prevent a privileged local user or the service account from modifying files. Reconciliation requires a complete authoritative reference list and reports, but does not delete, missing, invalid, orphaned, and temporary files. Files and the key need coordinated backups and access controls. Inspect existing child ACLs and restrict access to the service account before use; root ACL validation does not audit previously existing file ACLs.
